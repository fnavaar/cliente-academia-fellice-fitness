# AP-2026-09-17-2055 — página autenticada nunca deve confiar em sessão em cache sem validar

- Status: candidato
- Escopo: projeto do cliente
- Task/SPEC: F2-IMP-006 / SPEC-2-002 (debug de teste humano)
- Sinal: página autenticada que só checa `authStore.isValid` (token em localStorage) abre "logada" com token de usuário já removido — estado fantasma: UI logada, lista vazia, sem mensagem de erro. O teste humano capturou na hora ("ao colocar o link no navegador, já abriu direto").
- Evidência: screenshot do consultor mostrando /visao com botão Sair e 0 tentativas; correção no bootstrap da página — `authRefresh()` valida o token contra o servidor antes de carregar; em 401/403 a sessão é limpa e o login é exigido com mensagem clara. Aprovado no mesmo teste humano (v0.0.58).
- Regra reutilizável: toda página autenticada deve validar a sessão com o servidor no bootstrap (authRefresh) e tratar 401/403 limpando a sessão — `authStore.isValid` local não prova que o usuário ainda existe. Após remover usuários de teste, orientar o testador a recarregar com cache limpo.
- Quando aplicar: qualquer tela autenticada (fila, visão, painéis) em apps PocketBase/Skip.
- Quando não aplicar: páginas públicas.
- Confiança: alta — comportamento reproduzido pelo teste humano e correção aprovada.
- Privacidade: sem segredo, dado pessoal ou conteúdo bruto.
